3Que Blocker

Fetches a profile-ID blocklist from your server and applies it on Facebook and Threads.

Blocklist source

For a Firebase backend, paste the published document URL: https://firestore.googleapis.com/v1/projects/<project>/databases/(default)/documents/blocklist/current — reporting and suggestions wire themselves up from it. Plain JSON endpoints also work: ["100001234567890"], {"ids":[…],"usernames":[…]}, {"blocked":[{"id":"…","username":"…"}]}, or a newline-delimited list.

Sent as Authorization on each request. Stored in synced extension storage.

Uses If-None-Match, so an unchanged list costs almost nothing.

Layer 1 — Hide content (safe, always available)

Suppresses posts and comments authored by listed profiles. Sends no requests and changes nothing on your account.

Layer 2 — Real platform blocks (opt-in)

Read before enabling. This performs genuine blocks on your account using the site's own internal request path — the same one the Block button uses. Bulk-mutating an account can trigger rate limits or a verification checkpoint. Keep dry run on until you have confirmed the strategy works, keep the caps low, and note that Layer 1 already hides everything without touching your account.

Normally the extension drives the site's own block code, which is safe and always current. This fallback instead hand-builds the HTTP request. During testing that was observed forcing the signed-in session to log out, and on Threads the REST paths return 404 regardless. Leave this off unless you are debugging.

Which accounts get blocked

There are usually far more clones on the list than one account can block without being checkpointed. Blocking someone whose profile is on your screen is what people do all day; working through a list of strangers is not, so the two are budgeted and paced separately.

Counts only accounts you have never seen. Zero means never block anyone who has not appeared on your screen.

Teaching it the block request

Meta rotates its GraphQL doc_ids and gates operations behind generated provider variables, so nothing is hardcoded. The extension reads the live values out of the page. If it reports no block mutation found, the module simply has not been loaded yet — open any profile and block one person by hand. The request is captured and its shape reused from then on.

Clone reporting

Lets people flag clone accounts from the page itself. Reports go to your own server for review; nothing reaches the blocklist until an admin approves it.

Leave blank to use the directory the blocklist URL lives in.

Moderation lives on your server, not in the extension: open <your server>/admin and sign in with the token the server was started with. Nothing admin-related ships to the people using this.

Diagnostics

Page capability moved here from the popup. It is read from the first open Facebook or Threads tab — open one, then press Reload.
